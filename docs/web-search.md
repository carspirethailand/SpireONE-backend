# ค้นเว็บของ Cendon AI (web-search.mjs)

ตัวค้นกลางแบบผู้ช่วย AI ทั่วไป: ล้างคำค้น → ค้น (เจ้าเดียวหรือหลายเจ้าพร้อมกัน) → รวมผล ตัดซ้ำ จัดอันดับ → ส่งให้โมเดลพร้อมเลขอ้างอิง `[n]` และการ์ดแหล่งที่มาให้หน้าแอป

## เปิดใช้

ไม่มีคีย์ = ไม่ยิงอะไรออกไป ระบบใช้ทางเดิม (Brave → RSS/Wikipedia) ต่อ

```
wrangler secret put TAVILY_API_KEY
wrangler secret put EXA_API_KEY
wrangler secret put FIRECRAWL_API_KEY
```

ลำดับเจ้า: ตัวแปร `SEARCH_PROVIDERS` (เช่น `exa,tavily`) ถ้าไม่ตั้งใช้ tavily → exa → firecrawl เฉพาะเจ้าที่มีคีย์
ราคาต่อเครดิตปรับได้ที่ `TAVILY_USD_PER_CREDIT` / `FIRECRAWL_USD_PER_CREDIT` (Exa บอกราคาจริงกลับมาเอง)

## โหมด

| โหมด | ใช้ที่ | ทำอะไร |
|---|---|---|
| `fast` | เครื่องมือค้นของ ReAct (`executeSearchInternal`), แชตระดับคิดเร็ว | ไล่เจ้าตามลำดับ เจ้าแรกที่ได้ผลจบ |
| `balanced` | แชตปกติ (`webSearch` depth 1) | สองเจ้าแรกพร้อมกัน รวมผลด้วย RRF |
| `deep` | แชตระดับคิดลึก (depth 2) | ทุกเจ้าพร้อมกัน ขอเนื้อหาเต็มหน้า |

เจ้าที่ติดโควตา (429/402) พัก 5 นาที · ล่ม/ช้าเกิน พัก 1 นาที แล้วไปเจ้าถัดไป

## ความเป็นส่วนตัว

- ส่งออกเฉพาะคำค้นที่ตัดเบอร์ อีเมล ลิงก์ เลขตัวถัง ทะเบียน เลขยาว ๆ และพิกัดออกแล้ว ไม่มีชื่อหรือบัญชีผู้ใช้
- ข้อความจากเว็บถูกบอกโมเดลว่าเป็นหลักฐาน ไม่ใช่คำสั่ง (กัน prompt injection จากหน้าเว็บ)
- ผู้ให้บริการทั้งสามอยู่ในตารางผู้ประมวลผลของหน้า /privacy

## ทดสอบเทียบเจ้า

- ในเครื่อง: `TAVILY_API_KEY=… EXA_API_KEY=… FIRECRAWL_API_KEY=… node tools/search-bench.mjs [--mode=deep] [--limit=12]`
- ในระบบจริง (ใช้คีย์ใน Worker ไม่ต้องคัดลอกคีย์ออกมา): แอดมินเรียก
  - `GET /api/admin/search-status` — เจ้าที่ตั้งคีย์ไว้และลำดับ
  - `POST /api/admin/search-bench {"mode":"balanced","limit":12}` — ตารางเทียบ (สำเร็จ, p50/p95, ความเกี่ยวข้อง, ภาษาไทย, แหล่งน่าเชื่อถือ, วันที่, ต้นทุน, ผลซ้ำระหว่างเจ้า)
  - `POST /api/admin/search-try {"q":"…","mode":"balanced"}` — ลองคำค้นเดียว

ชุดคำค้น 12 ข้อ (`BENCH_QUERIES`) ครอบคลุม: เรียกคืนรถ ราคาซ่อม อาการ EV ขั้นตอนราชการ สเปกภาษาอังกฤษ ข่าว 7 วัน กระทู้ต่างประเทศ ความรู้ทั่วไป พ.ร.บ. และค้นหาศูนย์บริการในพื้นที่
ค่า `relevant` วัดจากคำที่คาดว่าคำตอบที่ดีต้องมี — เป็นตัวชี้วัดคร่าว ๆ ยังไม่ใช่การให้คนหรือโมเดลตัดสินคุณภาพคำตอบ
